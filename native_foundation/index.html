    Native physical sessions¶

    The property and source delivery catalog connects all 32 chemicals 1.5.2 public modules to native entry points, retained qualification results and separate EOS/flash responsibilities. It also lists the existing data adapters and shared sources. This is a responsibility map, not a claim of drop-in upstream API compatibility or empirical accuracy for every material. External source files remain caller-supplied; production does not import chemicals.

    Inspect and choose property methods¶

    ComponentPropertyPackage.selection_report(property_id, temperature_K=..., pressure_Pa=...) lists every declared candidate, source ID, unit, temperature/pressure domain, missing input and the selection reason. It inspects declarations without trying alternative formulas. with_selection returns a new package whose choices are used by ordinary evaluation, caloric integrals, transport, virial gas and VLE.

    Three policies are available:

    • PropertySelectionPolicy() preserves declaration order, preferring a candidate whose declared domain contains the requested state.
    • PropertySelectionPolicy("correlation", correlation_id) chooses that exact curve.
    • PropertySelectionPolicy("source_priority", source_priority=("b", "a")) permits only the listed source IDs and orders candidates within that shortlist. Domain compatibility is checked before priority. The list is a caller choice, not a claim about scientific quality.

    If all permitted candidates are outside their declared ranges, the selected curve is still governed by the evaluator's raise/warn/ignore policy. Mathematical failure never selects another curve. A missing pressure remains a missing input, and a source shortlist with no match raises PropertySelectionError with its complete report.

    This self-contained synthetic example changes which vapor-pressure curve the existing flash calculation consumes:

    import json
from dataclasses import replace
from math import log

from chemworld.examples.native_flash_research import synthetic_vle_properties
from chemworld.physchem import PropertySelectionPolicy
from chemworld.physchem.flash_units import VLEPropertyPackage, tp_flash
from chemworld.physchem.property_reports import R_J_PER_MOL_K

model = synthetic_vle_properties()
light = model.packages[0]
original = light.by_property("vapor_pressure")[0]
alternative = replace(
    original, correlation_id="alternative-pressure",
    coefficients={**original.coefficients, "A": log(1e5) + 30000 / R_J_PER_MOL_K / 345},
    metadata={"source": {"source_id": "example-b"}},
)
light = replace(light, correlations=(*light.correlations, alternative)).with_selection({
    "vapor_pressure": PropertySelectionPolicy("correlation", "alternative-pressure"),
})
model = replace(model, packages=(light, model.packages[1]))
restored = VLEPropertyPackage.from_dict(json.loads(json.dumps(model.to_dict())))
result = tp_flash(restored, {"light": .5, "heavy": .5},
                  temperature_K=350, pressure_Pa=1e5)
assert result.vapor_fraction == 0
assert restored.packages[0].selection_report(
    "vapor_pressure", temperature_K=350).selected_id == "alternative-pressure"

    For source-backed cards, pass selection_policies to PropertyInputCard.combine to retain overlapping alternatives, or call card.with_selection(...). Each curve's declared source must agree with its uncertainty/source envelope. Original source records and extra provenance survive selection and JSON; a contradictory segment source is rejected instead of relabelled.

    ConstantDatabase.inspect_value(identity, field_id, methods=...) reports every requested method, including unavailable files, missing identities/fields/values, unknown units, ambiguous records and conflicting values. Derived data readers share this API. It also retains unevaluated correlations and temperature series; use point= for an explicit series point. IdentifierDatabase.inspect_search likewise preserves all source candidates and distinguishes missing sources from no match, multiple registry identities and structural-field conflicts. Neither diagnostic chooses a record, merges identities or downloads external data.

    Critical estimates as explicit inputs¶

    hekayati_raeissi_critical estimates missing critical properties using molecular weight and either saturated liquid molar volume at 298.15 K or a supplied critical volume. Supply at least one of critical temperature and pressure. A supplied critical volume selects a different fitted equation from the saturation-volume route; passing an estimated volume back as Vc deliberately changes the model. Known critical values are preserved, including when both temperature and pressure are supplied. This does not reconcile inconsistent measurements.

    Use estimate_critical_property to keep sources, units, component identity and the selected equation with each derived result. Select output_property when more than one field is missing. Estimates remain configuration inputs and never overwrite measured constants:

    from chemworld.data.scientific_inputs import InputValue
from chemworld.physchem import (
    ComponentSpec, CubicEOSSpec, estimate_critical_property,
    eos_component_from_critical_inputs, evaluate_cubic_eos,
)

component = ComponentSpec("toluene", "C7H8", cas_number="108-88-3")
inputs = {
    "MW": InputValue(92.13842, "g/mol", None, "Explicit example input"),
    "V_sat": InputValue(.10686, "L/mol", None, "Saturated liquid at 298.15 K"),
    "Pc": InputValue(41.08, "bar", None, "Explicit example critical pressure"),
}
temperature = estimate_critical_property(
    component, method="Hekayati_Raeissi", parameters=inputs, output_property="Tc",
)
eos_component = eos_component_from_critical_inputs(
    component, Tc=temperature, Pc=inputs["Pc"],
    omega=InputValue(.2, "dimensionless", None, "Explicit example acentric factor"),
)
state = evaluate_cubic_eos(
    CubicEOSSpec("estimated", "peng_robinson", (eos_component,)), {"toluene": 1},
    temperature_K=700, pressure_Pa=1e6,
)

    The fitted equations and coefficients were read from the public chemicals 1.5.2 implementation attributed to Hekayati and Raeissi (2020, DOI 10.1002/aic.17004); the original paper was not directly verified. The native implementation expands those equations independently and has no chemicals runtime dependency. Reference agreement and positive fit outputs do not establish predictive accuracy for an arbitrary material. Missing, nonpositive and nonfinite inputs are rejected; saturation-volume predictions also require a critical temperature above 298.15 K. There is no implicit source ranking, fit selection by compound name, uncertainty estimate or new EOS runtime.

    Derived parameters in finite processes¶

    critical_correlation_input binds selected ConstantValue, CriticalEstimate and unit-bearing InputValue parameters to the existing volume or virial correlations. Supply the application range and an InputSource for the derived model. Each parameter's original report remains in metadata["parameter_sources"] through the property card and JSON. No measured source field is overwritten. Source aliases such as ChemSep's CriticalTemperature and CriticalVolume use the original database mapping. Their source field names and units remain in the report while the consumer converts them to SI and checks the component identity. estimate_critical_property(..., method="Zc_definition", parameters={"Tc": ..., "Pc": ..., "Vc": ...}) explicitly identifies the derived critical compressibility.

    from chemworld.data.scientific_inputs import InputSource
from chemworld.physchem import critical_correlation_input
from chemworld.physchem.data_conflicts import DataSourceProvenance

model_source = InputSource(DataSourceProvenance(
    "example-derived-volume", 0, "Explicit Rackett application using estimated Tc",
    version="1", license="synthetic example",
), "synthetic")
volume_input = critical_correlation_input(
    component, family="volume", method="Yamada_Gunn",
    parameters={"Tc": temperature, "Pc": inputs["Pc"], "omega": .2},
    temperature_range_K=(300, 400), source=model_source,
)

    Combine this volume card with explicitly selected heat capacity, viscosity and conductivity cards using PropertyInputCard.combine, then use the existing LiquidTransportProperties and FiniteTransportSpec. Source-backed volume fits can also consume these estimates as their declared supplemental inputs through VolumeDatabase.property_input. Source-owned coefficients cannot be overridden.

    For mixtures, LiquidTransportProperties.volume_mixing_method selects Amgat (the default), Rackett_mixture, COSTALD_mixture or COSTALD_mixture_compressed. The optional volume_mixing_parameters map is keyed by the existing component IDs: Rackett needs Tcs/Pcs/Zrs; COSTALD needs Tcs/Vcs/omegas. Molecular weights come from those components. Compressed COSTALD also requires explicit saturation-pressure parameters. Provide volume_mixing_note to identify their source and scope. Each finite transfer uses the current reservoir temperature, declared pressure and actual composition; JSON snapshots retain the selection. Amgat uses the current pure volumes and rejects frozen-volume overrides. Liquid enthalpy is still the separately declared additive model, so these volume laws do not establish a complete liquid EOS.

    Pure gas heating uses VirialGasThermodynamics and the original coupled solver. Its ideal heat-capacity datum can be outside the residual coefficient's domain: the ideal integral must cover its own reference path, while residual Helmholtz terms must be valid at every actual gas state. Neither domain is silently widened. Unlocated constant-volume observations retain an explicit single application temperature; solid volumes remain solid properties. They cannot supply an undeclared temperature-dependent liquid process.

    Source-backed transport inputs¶

    The Lennard-Jones, viscosity, conductivity and interface databases expose 19 external source tables containing 4,573 records. Select a source explicitly: ViscosityDatabase.property_input, ConductivityDatabase.property_input, InterfaceDatabase.property_input and LennardJonesDatabase.viscosity_input return the original PropertyInputCard. Tables are read from a caller-supplied directory; native execution does not import chemicals or download missing data. Missing identities and unknown validity intervals are reported, not filled in.

    PropertyInputCard.combine(cards, reference_note=...) assembles selected inputs for the same complete component declaration. It retains source and uncertainty metadata, shares identical declarations and rejects conflicting data or caloric references. Choose one correlation where the same property domains overlap; input order never selects a preferred source. A transport source alone does not provide heat capacity, density or a caloric datum. Supply those explicitly:

    from chemworld.physchem.property_inputs import PropertyInputCard
from chemworld.physchem.transport_devices import FiniteTransportSpec, LiquidTransportProperties
from chemworld.world.transport_world import transport_world_spec

def source_backed_liquid_world(viscosity, conductivity, calorics_and_density, bounds):
    card = PropertyInputCard.combine(
        (viscosity, conductivity, calorics_and_density),
        reference_note="Explicit source choices and liquid enthalpy reference",
    )
    if card.reference is None:
        raise ValueError("Supply an explicit liquid enthalpy reference")
    key = card.package.component.identifier
    properties = LiquidTransportProperties(
        (card.package,), temperature_bounds_K=bounds,
        pressure_Pa=card.reference.pressure_Pa,
        caloric_references={key: card.reference},
    )
    return transport_world_spec(
        FiniteTransportSpec(properties),
        feed_mole_fractions={key: 1.0}, receiver_mole_fractions={key: 1.0},
        feed_temperature_K=300, receiver_temperature_K=300,
    )

    The finite liquid apparatus consumes these curves during actual pump, pipe and heat-exchanger calculations. Mixtures use declared ideal volumes, log viscosity and DIPPR9H conductivity. The optional viscosity_pressure_parameters mapping selects Lucas for named components using critical_temperature_K, critical_pressure_Pa and acentric_factor; each affected package must also provide its vapor_pressure curve. Saturation viscosity and pressure are evaluated at the current temperature, and the actual reservoir pressure enters the correction. Missing baselines, temperatures above Tc and pressures below Psat are rejected. Input JSON and full runtime snapshots retain this declaration.

    ideal_gas_transport_state(packages, amounts, T, P, references) supplies the same FluidState, molar enthalpy and total volume tuple for gas pipe and heat-transfer consumers. It uses explicit ideal-gas volume, Wilke viscosity and Wassiljewa–Herning–Zipperer conductivity; it does not imply a dense EOS or a compressible-flow solver. Amounts and reference maps use canonical component IDs. LJ binary diffusivity can feed the existing conservative finite-volume operator. Interface tension feeds Young–Laplace pressure and the pump's pressure-load function; fixed-curvature qualification does not describe dynamic wetting.

    All 19 sources have process-consumption examples with independent equation checks. Supplementary properties in those examples are explicitly synthetic. Material prediction accuracy is a separate question. At large NTU, heat transfer can reach the stream-capacity limit: changing conductivity need not measurably change the outlet heat, even though the property is correctly consumed.

    Pure virial coefficients¶

    virial_correlation declares seven second-virial methods (Pitzer_Curl, Abbott, Tsonopoulos, Tsonopoulos_extended, Oconnell_Prausnitz, Xiang, Meng) and two third-virial methods (Orbey_Vera, Liu_Xiang) for the existing property package and input card. For example:

    from chemworld.physchem import virial_correlation, virial_temperature_report

curve = virial_correlation(
    "Tsonopoulos",
    parameters={"Tc": 425.2, "Pc": 3.8e6, "omega": 0.193},
    temperature_range_K=(300, 900),
    source_note="Explicit example critical parameters; application range chosen by caller",
)
value, first, second, third = virial_temperature_report(curve, temperature_K=510)

    Inputs use K, Pa and m³/mol; B is m³/mol and C is m⁶/mol². Signed coefficients are valid. virial_derivatives and virial_fast return the value through the third temperature derivative; virial_vector and virial_matrix apply the same kernel to explicit parameter sets. They do not generate cross parameters or perform mixture rules. All parameters remain fixed during differentiation.

    virial_value(..., order=-1) and order=-2 provide the documented indefinite integrals for Pitzer–Curl, Abbott and the two Tsonopoulos variants, with zero constants in the dimensional-temperature basis (log(T / 1 K)). Other methods do not declare these indefinite integrals. Normal integrate_correlation remains available for definite integrals within the declared application range.

    Extended Tsonopoulos requires explicit a and b, or a polar selection with species_type and the dipole in debye where required. The default documented polar convention includes methanol and the zero-dipole alkanol limit; explicitly select convention="chemicals_1_5_2" to reproduce that API's different behavior. Meng requires explicit a, or polar={"dipole": ..., "haloalkane": ...}. Choices and source notes survive JSON. Unknown classes and conflicting choices are rejected. Xiang/Liu constants were recovered from public calls in their documented mathematical basis and checked on separate inputs; their original paper tables have not been directly verified. Development mathematical agreement does not establish material accuracy or the validity of a truncated gas EOS.

    External density and volume sources¶

    chemworld.data.volume.VolumeDatabase(data_root) reads explicitly supplied Density tables and the existing ChemSep/VDI sources. It uses the same lazy identity and source database as other property inputs. Call db.volumes("64-17-5", method="PERRY_VOLUME") to inspect candidates, then db.property_input("64-17-5", component, method="PERRY_VOLUME") to obtain a normal PropertyInputCard; its evaluate_state consumes liquid density and molar_volume with the component's molecular weight.

    Select curve_id if a source has multiple candidates. Missing critical inputs must be supplied in parameters; unknown temperature bounds require temperature_bounds_K. Source coefficients cannot be overwritten. CRC constant observations require application_temperature_K and application_note and remain single points. VDI tables require interpolation="linear"; missing intervals and extrapolation are rejected. These temperature paths do not imply an independent pressure equation or caloric data. Source identity and molecular weight must agree with the component. External scientific datasets are not bundled or silently discovered through an upstream library.

    Use the same session through other entry points¶

    from chemworld.runtime import ChemWorldRuntime
from chemworld.world.surface_world import surface_world_spec

spec = surface_world_spec(terminal_assay=True)
session = ChemWorldRuntime(composition=spec, observation_noise_mode="keyed")
session.reset(seed=12)
result = session.execute({"operation": "add_component", "component": "CO-feed",
                          "amount_mol": 2e-5})
reading = session.execute({"operation": "measure", "instrument": "gas_pressure"})
for channel in reading.observation.channels:
    print(channel.channel_id, channel.value, channel.unit, channel.quality)
session.close()

    ChemWorldEnv(composition=spec) provides the Gym reset/step interface over the same runtime. chemworld.eval.runner.run_agent accepts composition=spec.to_dict() for an Agent. Both entry points retain transaction outcomes, physical duration, resource accounting and the native observation in info.

    To execute JSON actions from the CLI, save spec.to_dict() as world.json and each action as a separate JSON file, then run:

  --actions feed.json pressure.json --format json --trajectory run.jsonl \
  --snapshot continuation.json

    The CLI refuses to overwrite an existing trajectory or snapshot. Snapshots and trajectory provenance contain private simulator state/configuration for evaluator continuation and replay; they are not Agent observations. JSON can reorder map keys, so physical replay uses a numerical tolerance (the CLI default is 1e-5), while categorical outcomes must agree. Replay requires the original runtime semantics; current main does not substitute for frozen paper physics.

    Readings, time and reuse¶

    Native channels own physical values and units, uncertainty, quality, axes and acquisition times. Invalid or unobserved channels are explicit; a valid physical reading need not fit in [0, 1]. The fixed Gym scalar view is a derived compatibility projection. Use info["native_observation"] or session results for the complete channel record. Calling observe() returns cached readings and does not acquire another sample.

    In-situ acquisition advances the world through the same physical integrator. Offline analysis keeps its acquisition snapshot and accounts for analysis time separately. A task requiring a final assay first freezes production, then ends after that assay; it does not advance the frozen production vessel again.

    session.snapshot().save(path) and ChemWorldRuntime.from_snapshot(SessionSnapshot.load(path)) support private continuation with compatible bindings. session.reset() creates a fresh world. Evaluator-only reset(options={"scope": "material", "vessel_ids": ["reactor"]}) replaces that material while retaining attached stationary equipment and its calibration. Partial initialization retains clocks, budgets and RNG state; it is not a free Agent operation. SessionSnapshot is also exported from chemworld.runtime.

    Current private sessions use chemworld-session-v2. Their phase identities and material coordinate order survive sorted JSON, including retained samples; pending events, apparatus queues, RNG and resource events remain part of the same continuation. Configuration comparison uses the installed model codecs. Supply the same domain_modules registry when restoring a local extension; callable names in a saved binding describe installed code and are never imports.

    Older v1 sessions require an explicit SessionSnapshot.migrate_v1(payload) call. This converts the encoding only when runtime semantics match and omitted assembly order is unambiguous. Multiple records without saved order require the original ordering information. Restoration still checks the complete execution binding. Older physical-world inputs retain their supported boundary conversions; this does not authorize reinterpretation of frozen session evidence.

    Model and acceptance boundaries¶

    The gas reaction, five-step surface rates, finite material transfers, shared internal-energy/heat-capacity balance and heater model are executable physics. The tests' injected numerical failure, process failure and invalid readout are interface fixtures, not implemented failure mechanisms. Thermal stopping uses a real event. Property tables and rate parameters are finite synthetic contracts. Surface flow, arbitrary thermodynamics and new electrode kinetics remain outside this foundation slice.

    Activity thermodynamics and liquid property consumption¶

    The existing ActivityModelSpec supports ideal, Margules, Wilson, NRTL, UNIQUAC, regular solution, Flory–Huggins, Hansen and six UNIFAC variants through a shared excess Gibbs-energy contract. Request excess H, S, Cp, analytic temperature/composition derivatives and partial molar quantities with activity_thermodynamic_report(model, composition, temperature_K=...) from chemworld.physchem. activity_infinite_dilution(...) evaluates exact zero solute concentration in explicitly supplied remaining solvent proportions. The results are immutable and provide to_dict() for JSON output.

    regular_solution_model(...) compiles explicit reference molar volumes, solubility parameters and directed interaction corrections. Without a correction request it records explicit zero corrections; incomplete supplied pairs fail. hansen_activity_model(...) consumes source-bearing HansenParameters and unit-bearing reference volumes, with an explicit alpha. These models hold reference volumes and cohesive parameters constant in temperature. The sum of opposite regular-solution corrections is identifiable; fitting cannot identify the two directions separately. Source data remain in the model's provenance.

    Pass activity_model=model to the existing evaluate_property_state(...) liquid interface to combine these responses with declared pure-liquid caloric references. Supported requests include enthalpy, cp, entropy, chemical_potential and activity_coefficient. Component IDs must match the property packages. An activity-only request needs no unrequested heat-capacity data; entropy and chemical potentials require explicit entropy references. The model supplies neither a volume law nor a constant-volume energy closure.

    chemworld.data.ActivityCalibration fits explicit model coefficients through the existing bounded calibration driver. Its ScientificTable conditions contain temperature and all component fractions; observations may contain ln-gamma, GE, HE, SE or CpE. Training and holdout groups remain separate, and fitting retains the actual evaluation ledger. These functions do not imply a complete interaction-parameter database, group-contribution coverage or measured material accuracy. Asymmetric Margules results now follow an integrable three-suffix equation; the former componentwise expression was thermodynamically inconsistent.

    unifac_activity_model(...) accepts explicit molecular subgroup counts, source-bearing subgroup parameters and every directed unlike-main-group interaction. Versions 0–5 select original/LLE, Dortmund/NIST, PSRK, VTPR, Lyngby/Larsen and KT. The returned ActivityModelSpec uses the same caloric, derivative, dilution, calibration and liquid-property interfaces above. Group topology is discrete; only continuous interaction coefficients are fit.

    The chemworld.data readers read_unifac_subgroups, read_unifac_interactions, iter_ddbst_text and iter_ddbst_sqlite consume explicit local source files. select_unifac_interactions requires an explicit choice for overlapping revisions and retains superseded records. unifac_model_from_assignments maps declared native component identities to source assignments; automatic DDBST numbering applies to versions 0/1/2 only. Missing interactions and invalid assignments fail explicitly. Source temperature ranges remain provenance; they are not automatically enforced as model domains. The source tables and the reference package are not runtime dependencies.

    Predictive PR78 interactions¶

    PPR78Spec binds explicit molecular groups to a selected original or extended interaction table and its provenance. Missing or asymmetric pairs are errors. ppr78_interaction_response supplies k and its first three temperature derivatives.     Excess-Gibbs cubic mixing¶

    GibbsExcessMixingSpec connects the existing activity models to PR/SRK through Huron-Vidal, exact MHV, MHV1, MHV2 or Wong-Sandler. Set it as CubicEOSSpec.ge_mixing. MHV1/2 require explicit q coefficients; Wong-Sandler requires every unlike binary pair. Quadratic and predictive interactions cannot be silently combined with GE mixing. Exact MHV requires a differentiable zero-pressure liquid branch.

    The original EOS roots remain the state solver. Fugacity, enthalpy and entropy differentiate one residual Helmholtz potential, including Wong-Sandler's temperature-dependent covolume. Thus selecting a new mixing rule changes both phase behavior and energy consistently. The existing activity families and all six UNIFAC variants can use this interface; model choice and material calibration remain explicit.

    Unified homogeneous phase properties¶

    PhasePropertyModel freezes existing component packages, phase, references, activity/EOS choices and explicit transport declarations.     PhaseTransportSpec selects one of 12 existing mixture transport methods. Pure curves are evaluated at current conditions, with explicit method parameters; LBC consumes current volume, and Diguilio-Teja consumes pure surface tension at each boiling temperature. Fixed-composition correlations require composition binding. Missing sources or closures stay unavailable. This interface owns no inventory, clock or phase-split solver, and preserves existing JSON declarations.

    Multifluid mixtures, local criticality and fitting¶

    MultifluidModel combines explicitly supplied pure Helmholtz equations, oriented binary reducing parameters and departure terms. Import a complete declaration with chemworld.data.read_multifluid_model(path, source=...), or select named components from a caller-provided MultifluidSourceCatalog. Missing pairs are errors. The gas constant convention, component order, original source constants and fitted parameters remain explicit. Production does not download parameters or depend on teqp/CoolProp.

    The model's caloric_model() returns the existing MolecularCaloricModel with source-derived ideal references. Use it with MolecularIsochoricThermodynamics, MolecularStream and CoupledSystem to advance real inventories and account for heat and incoming enthalpy. Model selection does not create another inventory. These homogeneous consumers require a locally stable state. General phase selection is a separate calculation with explicitly declared density basins.
