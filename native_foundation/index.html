    Native physical sessions¶

    Thermodynamic and engineering APIs¶

    These examples run with the current Python package. Inputs carry physical units and explicit coefficients; outputs below are produced by the displayed code. The capability website also shows function signatures and a JSON/table toggle.

    Delivered thermodynamics includes activity derivatives and finite calibration, six UNIFAC variants with caller-supplied group data, Twu/PPR78 and GE cubic mixing, and a shared homogeneous-phase evaluator. Pure-fluid Helmholtz adds density roots, saturation, TP/PH/PS/T-rho flash and bounded thermal consumers. The example below isolates the ideal-gas limit; real-fluid use requires a sourced coefficient set and its application range. General associating/multifluid EOS remain future work.

    Engineering methods include friction, fittings, valves, meters, pumps, packed beds/towers, two-phase and open-channel flow, particle distributions and equipment geometry. Each declares its own physical assumptions and operating domain.

    Pure-fluid Helmholtz state¶

    Self-authored ideal-gas coefficients demonstrate inputs in K and mol/m³ and dimensional properties. Real fluids require sourced coefficients; this call checks homogeneous local stability.

    import json
from chemworld.physchem.helmholtz import HelmholtzFluid
from chemworld.physchem.helmholtz_terms import HelmholtzTerm

inputs = {'temperature_K': 400, 'molar_density_mol_m3': 20}

fluid = HelmholtzFluid(
    fluid_id="synthetic-monatomic", casrn="", molar_mass_kg_mol=0.04,
    gas_constant_J_mol_K=8.3, reducing_temperature_K=300,
    reducing_molar_density_mol_m3=1000, minimum_temperature_K=100,
    maximum_temperature_K=1500, maximum_pressure_Pa=1e9,
    ideal_terms=(
        HelmholtzTerm("IdealGasHelmholtzLead", {"a1": 0, "a2": 0}),
        HelmholtzTerm("IdealGasHelmholtzLogTau", {"a": 1.5}),
    ), residual_terms=(), source="Self-authored ideal-gas demonstration",
)
state = fluid.state(**inputs)
output = {key: state.to_dict()[key] for key in (
    "pressure_Pa", "enthalpy_J_mol", "cp_J_mol_K", "cv_J_mol_K",
    "compressibility_factor", "stability_scope",
)}

print(json.dumps(output, indent=2, ensure_ascii=False, allow_nan=False))

    {
  "pressure_Pa": 66400.0,
  "enthalpy_J_mol": 8300.0,
  "cp_J_mol_K": 20.75,
  "cv_J_mol_K": 12.45,
  "compressibility_factor": 1.0,
  "stability_scope": "homogeneous_local_only"
}

    Engineering flow meter¶

    Calculate differential pressure from mass flow, then invert it to recover flow. Installation conditions, fluid parameters and the correlation domain must satisfy the declaration.

    import json
from chemworld.physchem.flow_meters import LiquidOrificeSpec, liquid_orifice_pressure, liquid_orifice_mass_flow

inputs = {'pipe_diameter_m': 0.07366,
 'orifice_diameter_m': 0.05,
 'mass_flow_kg_s': 7.0,
 'density_kg_m3': 999.1,
 'viscosity_Pa_s': 0.0011}

spec = LiquidOrificeSpec(inputs["pipe_diameter_m"], inputs["orifice_diameter_m"], taps="corner",
    installation_note="ISO concentric sharp edge; compliant straight runs and roughness assumed")
properties = {key: inputs[key] for key in ("density_kg_m3", "viscosity_Pa_s")}
forward = liquid_orifice_pressure(spec, mass_flow_kg_s=inputs["mass_flow_kg_s"], **properties)
inverse = liquid_orifice_mass_flow(spec, differential_pressure_Pa=forward.differential_pressure_Pa,
    **properties)
output = {"forward": forward.to_dict(), "recovered_mass_flow_kg_s": inverse.mass_flow_kg_s}

print(json.dumps(output, indent=2, ensure_ascii=False, allow_nan=False))

    Pure virial coefficients¶

    virial_correlation declares seven second-virial methods (Pitzer_Curl, Abbott, Tsonopoulos, Tsonopoulos_extended, Oconnell_Prausnitz, Xiang, Meng) and two third-virial methods (Orbey_Vera, Liu_Xiang) for the existing property package and input card. For example:

    from chemworld.physchem import virial_correlation, virial_temperature_report

curve = virial_correlation(
    "Tsonopoulos",
    parameters={"Tc": 425.2, "Pc": 3.8e6, "omega": 0.193},
    temperature_range_K=(300, 900),
    source_note="Explicit example critical parameters; application range chosen by caller",
)
value, first, second, third = virial_temperature_report(curve, temperature_K=510)

    Inputs use K, Pa and m³/mol; B is m³/mol and C is m⁶/mol². Signed coefficients are valid. virial_derivatives and virial_fast return the value through the third temperature derivative; virial_vector and virial_matrix apply the same kernel to explicit parameter sets. They do not generate cross parameters or perform mixture rules. All parameters remain fixed during differentiation.

    virial_value(..., order=-1) and order=-2 provide the documented indefinite integrals for Pitzer–Curl, Abbott and the two Tsonopoulos variants, with zero constants in the dimensional-temperature basis (log(T / 1 K)). Other methods do not declare these indefinite integrals. Normal integrate_correlation remains available for definite integrals within the declared application range.

    Extended Tsonopoulos requires explicit a and b, or a polar selection with species_type and the dipole in debye where required. The default documented polar convention includes methanol and the zero-dipole alkanol limit; explicitly select convention="chemicals_1_5_2" to reproduce that API's different behavior. Meng requires explicit a, or polar={"dipole": ..., "haloalkane": ...}. Choices and source notes survive JSON. Unknown classes and conflicting choices are rejected. Xiang/Liu constants were recovered from public calls in their documented mathematical basis and checked on separate inputs; their original paper tables have not been directly verified. Development mathematical agreement does not establish material accuracy or the validity of a truncated gas EOS.

    External density and volume sources¶

    chemworld.data.volume.VolumeDatabase(data_root) reads explicitly supplied Density tables and the existing ChemSep/VDI sources. It uses the same lazy identity and source database as other property inputs. Call db.volumes("64-17-5", method="PERRY_VOLUME") to inspect candidates, then db.property_input("64-17-5", component, method="PERRY_VOLUME") to obtain a normal PropertyInputCard; its evaluate_state consumes liquid density and molar_volume with the component's molecular weight.

    Select curve_id if a source has multiple candidates. Missing critical inputs must be supplied in parameters; unknown temperature bounds require temperature_bounds_K. Source coefficients cannot be overwritten. CRC constant observations require application_temperature_K and application_note and remain single points. VDI tables require interpolation="linear"; missing intervals and extrapolation are rejected. These temperature paths do not imply an independent pressure equation or caloric data. Source identity and molecular weight must agree with the component. External scientific datasets are not bundled or silently discovered through an upstream library.

    Virial mixtures and gas consumers¶

    The public virial API also provides cross-parameter constructors, B/C mixture rules and composition derivatives. virial_gas exposes density- and pressure-form forward/inverse calculations. These mathematical kernels do not by themselves establish a mixture's material accuracy or phase stability.

    chemworld.data.virial_inputs.sourced_virial_input consumes an explicitly selected ConstantDatabase record (including HEOS constants), preserving source identity, units and missing fields. The caller declares the application range; critical constants alone do not supply a measured validity interval. The volume database also exposes CRC virial polynomials with the same explicit range rule.

    For a pure single-phase gas, PropertyInputCard.evaluate_state(gas_model="virial", ...) uses the B/C equations for pressure, density and compressibility. With explicit ideal caloric data it also evaluates consistent internal energy, enthalpy, entropy and heat capacities. VirialGasThermodynamics and virial_gas_batch_system connect this state to the common CoupledSystem for closed, fixed-volume heating, energy accounting and continuation. General nonideal mixture calorics, open-flow processes and phase equilibrium are outside this consumer contract. See tests/test_virial_consumers.py for runnable inputs.

    Run native sessions¶

    These development examples use the installed current runtime, without a model API key or upstream solver. Start with the finite synthetic CO oxidation model below, then use the domain-specific examples in the later sections. Python 3.11 or 3.12 is the validation target.

    Public functional checks live under tests/; bounded optional reference runners live under scripts/. The workstreams/world_foundation/ reports cited in this guide identify development records in the authoring repository. Those run outputs are not part of this public source synchronization; the included commands create new comparison results at the output path you choose.

    For the current ten cross-domain workflows, shared-clock boundaries and the separate source/install denominators, start with native domains. Both sequential and keyed detection are supported on the qualified shared-clock histories. Explicitly declared multi-device queues and idle-system material replacement use the same runtime, transaction and continuation machinery. The sections below also describe later scientific extensions; their individual acceptance scope does not follow automatically from stage-A completion.

    After installing the wheel or sdist in an isolated environment:

    python -m chemworld.examples.native_surface_research --bulk --mobile --terminal-assay
python -m chemworld.examples.reuse_native_equipment

    In a development checkout, prefix Python commands with uv run --no-sync. The first example feeds finite stocks, heats, measures, routes material and ends the task. --no-surface runs the same apparatus as an inert or bulk-only system; --bulk adds the declared bulk reaction. --mobile attaches a material-borne surface. Without it, the stationary surface remains on its vessel when gas moves.

    The second example uses the same heater model in inert, bulk, surface and combined systems. It initializes fresh material in the reactor between two batches and checks that the retained heater keeps its identity and calibration. It also binds one compiled physical world to two tasks: direct termination and termination followed by a required final assay. Their physical response before ending agrees.

    Use the same session through other entry points¶

    from chemworld.runtime import ChemWorldRuntime
from chemworld.world.surface_world import surface_world_spec

spec = surface_world_spec(terminal_assay=True)
session = ChemWorldRuntime(composition=spec, observation_noise_mode="keyed")
session.reset(seed=12)
result = session.execute({"operation": "add_component", "component": "CO-feed",
                          "amount_mol": 2e-5})
reading = session.execute({"operation": "measure", "instrument": "gas_pressure"})
for channel in reading.observation.channels:
    print(channel.channel_id, channel.value, channel.unit, channel.quality)
session.close()

    ChemWorldEnv(composition=spec) provides the Gym reset/step interface over the same runtime. chemworld.eval.runner.run_agent accepts composition=spec.to_dict() for an Agent. Both entry points retain transaction outcomes, physical duration, resource accounting and the native observation in info.

    To execute JSON actions from the CLI, save spec.to_dict() as world.json and each action as a separate JSON file, then run:

    chemworld render --composition world.json --seed 12 --noise-mode keyed \
  --actions feed.json pressure.json --format json --trajectory run.jsonl \
  --snapshot continuation.json
chemworld verify --submission run.jsonl

    The CLI refuses to overwrite an existing trajectory or snapshot. Snapshots and trajectory provenance contain private simulator state/configuration for evaluator continuation and replay; they are not Agent observations. JSON can reorder map keys, so physical replay uses a numerical tolerance (the CLI default is 1e-5), while categorical outcomes must agree. Replay requires the original runtime semantics; current main does not substitute for frozen paper physics.

    Readings, time and reuse¶

    Native channels own physical values and units, uncertainty, quality, axes and acquisition times. Invalid or unobserved channels are explicit; a valid physical reading need not fit in [0, 1]. The fixed Gym scalar view is a derived compatibility projection. Use info["native_observation"] or session results for the complete channel record. Calling observe() returns cached readings and does not acquire another sample.

    In-situ acquisition advances the world through the same physical integrator. Offline analysis keeps its acquisition snapshot and accounts for analysis time separately. A task requiring a final assay first freezes production, then ends after that assay; it does not advance the frozen production vessel again.

    session.snapshot().save(path) and ChemWorldRuntime.from_snapshot(SessionSnapshot.load(path)) support private continuation with compatible bindings. session.reset() creates a fresh world. Evaluator-only reset(options={"scope": "material", "vessel_ids": ["reactor"]}) replaces that material while retaining attached stationary equipment and its calibration. Partial initialization retains clocks, budgets and RNG state; it is not a free Agent operation. SessionSnapshot is also exported from chemworld.runtime.

    Current private sessions use chemworld-session-v2. Their phase identities and material coordinate order survive sorted JSON, including retained samples; pending events, apparatus queues, RNG and resource events remain part of the same continuation. Configuration comparison uses the installed model codecs. Supply the same domain_modules registry when restoring a local extension; callable names in a saved binding describe installed code and are never imports.

    Older v1 sessions require an explicit SessionSnapshot.migrate_v1(payload) call. This converts the encoding only when runtime semantics match and omitted assembly order is unambiguous. Multiple records without saved order require the original ordering information. Restoration still checks the complete execution binding. Older physical-world inputs retain their supported boundary conversions; this does not authorize reinterpretation of frozen session evidence.

    Model and acceptance boundaries¶

    The gas reaction, five-step surface rates, finite material transfers, shared internal-energy/heat-capacity balance and heater model are executable physics. The tests' injected numerical failure, process failure and invalid readout are interface fixtures, not implemented failure mechanisms. Thermal stopping uses a real event. Property tables and rate parameters are finite synthetic contracts. Surface flow, arbitrary thermodynamics and new electrode kinetics remain outside this foundation slice.

    The native acceptance covers fixed native/Gym/CLI/Agent histories, both observation noise modes, direct/assay endings, replay and retained equipment. Installation checks build both archives and run the installed modules outside the checkout, with Cantera absent and model keys removed from the child environment. Reported platform results apply only to actual runs; this is development acceptance, not a formal release or a claim of general chemical validity. See contribution guide for packaging and frozen releases.

    Properties at the current state¶

    ComponentPropertyPackage.evaluate_state(...) evaluates a pure state; evaluate_property_state(packages, amounts_mol, ...) evaluates a composition. Both use the existing component IDs, declared aliases and CAS identifiers. Supply temperature_K, pressure_Pa, phase and the requested quantities. The report retains units and validity warnings for each property. For example:

    from chemworld.physchem.curated_properties import curated_property_package

report = curated_property_package("7732-18-5").evaluate_state(
    temperature_K=400, pressure_Pa=1000, phase="gas",
    quantities=("cp", "enthalpy", "internal_energy", "density"),
)
cp = report.properties["cp"].quantity().to("J/(mol*K)")

    Energy values are molar J/mol, heat capacities J/(mol K), volume m³/mol and mass density kg/m³. The default caloric datum is explicitly sensible H=0 at 298.15 K; it supplies no formation enthalpy or absolute entropy. Supply a CaloricReference when another datum is needed. Entropy and chemical potential require an entropy datum. The six curated packages currently supply gas Cp and vapor pressure; their default material phase does not imply liquid Cp or transport data. Missing quantities raise an error.

    Gas states default to the ideal-gas closure. An explicit existing CubicEOSSpec selects PR/SRK volume, fugacity, departures and derivatives on the requested gas/liquid root. This is a single-phase evaluation; phase equilibrium belongs to the flash model. Its Cp derivative follows the selected outer root and does not support root-topology changes. validity_policy="warn" or "ignore" can evaluate beyond a correlation range, but this API retains the invalid-domain record under either policy.

    Native reactor and equipment consumers can share PropertyPackageThermodynamics with SpeciesCaloricModel data. They obtain U(n,T), Cv and composition derivatives from the same evaluations at the current candidate state. The common integrator owns time and heat accounting; material mixing solves the same U relation for temperature. Accepted states and authored operating intervals must remain inside the declared caloric domain. This additive caloric runtime does not claim a nonideal closed-volume EOS balance. Existing constant-Cv declarations delegate to this evaluation path; the older liquid volumetric-Cp model and fixed-capacity phase plateaus remain explicitly selected models. Variable-caloric phase change requires a flash/latent closure.

    Run python -m chemworld.examples.state_property_research in an installed environment for a property query and an actual variable-Cv reactor history. Its temperature dependence is synthetic and retains the original native U datum; it is an interface example rather than new material data. Production evaluation imports no reference backend. The optional physchem-ref tools are used only for the separate same-equation and model-bias checks documented in workstreams/world_foundation/NATIVE_PROPERTY_ACCEPTANCE.md.

    TP/PH flash and finite phase inventories¶

    VLEPropertyPackage combines existing property packages, explicit gas enthalpy references and a declared liquid activity model. tp_flash(...) updates K from the current liquid and vapor compositions; an optional existing gas EOS updates vapor fugacity and departure enthalpy. Liquid enthalpy is the temperature derivative of the same Psat/activity free energy, sharing the gas datum. ph_flash(..., pressure_Pa=..., enthalpy_J=...) holds total H fixed and solves T. Pure saturation uses an enthalpy lever rule. Missing/vanished phases carry zero inventory. Unreachable H and nonconvergence raise explicitly.

    TP returns a state query when no inlet H is supplied; its heat duty is then unavailable. With explicit feed_enthalpy_J, TP reports the heat required to maintain the specified T. PH reports zero added heat and its actual enthalpy residual. It does not close the balance by assigning the residual to a heater.

    This first slice supports one liquid plus one gas, two/three components and a convex ideal liquid or certified convex binary Margules liquid. Other activity models and uncertified/nonconvex liquids require the separate LLE/stability solver. Critical transitions and three-phase states are outside this model. The Raoult liquid thermodynamic model neglects liquid volume/Poynting work; its nominal liquid holdup is a separate geometric filling approximation. No exact liquid internal-energy/PV-work balance is claimed.

    FlashSystemSpec declares a finite constant-pressure thermal system. A native vapor_liquid_equilibrium component selects its enthalpy strategy through the existing physical advance coordinator. Candidate H is integrated once, PH closes each candidate, and accepted liquid/gas quantities occupy the normal phase ledger. The normal device, feed, material routing, measurement, transaction, resource and snapshot services consume that same inventory. Registered liquid species explicitly declare their carrier representation, preventing a second legacy solvent-volume inventory from being inferred from geometric volume. Element and carrier balance checks remain active.

    Run python -m chemworld.examples.native_flash_research for a PH query followed by actual finite feeding, cross-phase heating, a timed phase probe, transfer and termination. phase_state is an explicitly noiseless synthetic sensor, not a claim of experimental phase identification. See workstreams/world_foundation/NATIVE_FLASH_ACCEPTANCE.md for the fixed 27-state thermo comparison and development boundaries.

    Strict liquid stability and finite washing¶

    liquid_tpd_minimum(activity_model, composition, temperature_K=...) minimizes the actual tangent-plane distance on a deterministic set of simplex starts. equilibrate_liquids(activity_model, amounts_mol, temperature_K=...) minimizes constrained mixing Gibbs energy, refines equality of phase chemical potentials, checks component balances and repeats TPD searches on both resulting phases. A stable feed returns one liquid. A remaining negative post-split TPD rejects an unsupported additional phase. Binary/ternary models support at most two liquids; the finite numerical search is not a proof of exhaustive global optimization for arbitrary activity functions.

    mixing_chemical_potentials_RT reports ln(x_i gamma_i), relative to the common pure-liquid standard and divided by RT. Common pure reference terms cancel across equal-T liquid phases; these are not fabricated absolute chemical potentials. Activity coefficients use the existing parameter model, shared with the property and contact calculations.

    StrictLiquidSystemSpec declares an isothermal material law, component molar holdups and finite wash policy. A liquid_equilibrium component and matching CompositionPhysics.liquid_models entry enable the normal mix/wash, feed, clock, measurement, material routing and snapshot services. Actual wash liquid comes from a finite named supply; discarded material is an explicit molecular outlet. A miscible wash retains one mixed liquid. Droplet entrainment uses the same inventory transfer function as the empirical contact model. The phase probe reports liquid count and second-liquid fraction as synthetic native channels. Mixing heat and PV work remain explicitly unmodeled in this isothermal slice; no heat-control operation is implied.

    The older distribution-coefficient contact model remains a separate model. Its minimum_tpd_like includes an empirical partition drive and is explicitly marked thermodynamic_stability_certified=False. Strict liquid equilibrium does not use that drive or fall back to it after a solver failure.

    Run python -m chemworld.examples.native_liquid_research for finite mixing, washing, a timed observation, transfer and termination. The example's Margules parameters and component identities are synthetic. See workstreams/world_foundation/NATIVE_LLE_ACCEPTANCE.md for common-tangent, ternary and actual PhasePy validation.

    Conservative diffusion primitive¶

    chemworld.physchem.finite_volume provides planar and spherical one-dimensional Fick operators in SI units. DiffusionMesh defines physical volumes and face areas; ConservativeDiffusion.evaluate(amounts_mol) returns molar derivatives and signed face rates without advancing time. Positive prescribed boundary flux means outward flux in mol/(m² s). A spherical center requires symmetry.

    operator.couple(existing_inventory_keys, process_id=..., owner_id=..., boundary_enthalpies_J_mol=...) supplies a process and material ports to an existing CoupledSystem. Explicit boundary enthalpies are required for open boundaries. BDF/Radau use the assembled sparse stencil; outward fixed-flux depletion stops at its actual event. The caller retains inventory ownership. This is the shared spatial primitive for subsequent electrode/particle models; these mathematical consumers do not implement a battery or a new PDE runtime.

    Finite dynamic distillation¶

    DynamicColumnSpec reuses ShortcutColumnSpec for the hardware envelope and VLEPropertyPackage for the thermodynamic law. It has 2–8 equilibrium trays, a finite reboiler, condenser and product collector. Each compartment advances actual component amounts and H; task-18 PH closes its phase allocation at each candidate. Vapor withdrawal and liquid overflow use declared finite holdup laws. Heat and material streams enter one shared BDF advance. This model excludes full tray hydraulics, pressure-drop networks and simultaneous reactions.

    A dynamic_distillation component and matching CompositionPhysics.column_models entry select this strategy. dynamic_column_world_spec(spec, initial, ...) constructs a native apparatus from explicitly supplied properties and initial inventories. Real distill, heat/wait and timed observations use the common coordinator; dry, flood, temperature, collection and native vessel-volume boundaries stop at their actual roots. Product history records actual collector increments over time. collect_fraction moves actual liquid n and H into its separate retained phase; it never resets the column or manufactures recovery.

    Distill controls are target temperature, duration and finite reflux_ratio. Native event JSON additionally accepts numeric full_reflux: 1 (with the usual required reflux field present); full_reflux: 0 resumes finite collection. The unchanged fixed Gym numeric carrier explicitly rejects this additional field and directs callers to event JSON. The old distillation component remains a labelled shortcut_estimate, without stage histories or a fallback from failed dynamic integration.

    PhaseLedger alone owns bulk n. Material and stationary support H occupy separate typed slots. Replacing material retains apparatus heat and device calibration, then equilibrates the new fluid plus retained body through PH. Batch reset uses the declared initial thermal boundary while retaining hardware settings. Snapshots retain all compartments and controls. The synthetic phase probe observes the reboiler compartment.     Selected native TDB/CEF material¶

    TdbDatabase accepts declarative TDB text with an explicit InputSource. CefPhaseModel evaluates the selected phase's sublattices, vacancies, charged constituents, ordering, magnetic and caloric contributions without an upstream runtime dependency. CefMaterialSpec adds an authored temperature interval, fixed pressure, holder heat capacity and mechanical atom-molar volume. calphad_world_spec(model, element_amounts_mol=..., temperature_K=...) installs that material on the existing solid/thermal strategy and finite-power device.

    Inventory keys are real TDB elements and amounts are mol of nonvacant atoms. Charged constituents and vacancies belong to the committed phase's site fractions; they do not create another material inventory. The model is stored once in the versioned calphad_material physical declaration. Its equipment record only references that binding. calphad_phase_meter reads committed temperature, element amounts and site fractions. It does not synthesize a diffraction spectrum or pretend that real elements are the old A/B counters.

    heat/wait integrate the same finite-inventory total enthalpy. Internal constitution and relaxed heat capacity come from the common constrained root; temperature comes from the common caloric root. Constant element amounts are eliminated from numerical unknowns in this heat-only process, and every contribution must have zero matter rate. Holder heat is retained on material replacement; snapshot continuation, history replay, failure settlement and thermal controls retain their existing contracts.

    This consumer holds one explicitly selected solid or liquid phase at a local internal minimum. It does not select a globally stable multiphase assemblage. Line compounds may have valid thermal response but underdetermined individual element potentials; no arbitrary multiplier is reported as a determined chemical potential. Nonpositive effective heat capacity, failed constraints and unsupported derivative boundaries reject the closure. Gas EOS and general phase selection require their separately declared models. The mechanical volume is authored geometry, not a pressure derivative inferred from TDB.

    ChemSageDatabase.from_file(path, source=...) accepts original declarative ChemSage DAT input on that same Gibbs/material interface. The immutable input retains source provenance, phase occurrences, suppression flags, original stoichiometry, all intervals and model metadata. Repeated labels use NAME#OCCURRENCE1, etc.; phase_records exposes the original labels and records. G and Cp descriptions compile to the common caloric evaluator, including reference H/S, latent heat, extended powers and magnetic terms. QKTO uses the declared chemical groups and directional Kohler/Toop exponents. Auxiliary electron balances constrain CEF internal constitution without adding atoms.

    Source suppression requires explicit activate_suppressed=True. Nonzero excess pressure coefficients require an explicit excess_pressure_unit="Pa" or "bar". Select MQMQAPhaseModel for SUBG/SUBQ quadruplet phases. It consumes source coordination numbers and their mixed/reciprocal recurrences, reference pair energies, both entropy models, and directional G/Q/R interactions with chemical groups and ternary terms. Quadruplet fractions are internal constitution; actual atom amounts remain in the existing material inventory. It shares Gibbs responses, constrained constitution and CefMaterialSpec with CEF. Original pair atoms and quadruplet charge must be consistent; the model rejects contradictory input and preserves its original declarations. Legacy annotations with no defined energy effect remain visible in diagnostics. Nonzero MQMQA source auxiliary balances need a separately declared consumer. The CEF consumer rejects MQMQA input. Unsupported real-gas, aqueous, volume and group override physics are also rejected explicitly. JSON stores original input and declared options, then recompiles through known native codecs.

    Two-site surface interactions¶

    Pass MultisiteSurfaceSpec to the existing surface_world_spec(surface_spec=...).     Parameter and measurement inputs¶

    Run uv run --no-sync python -m chemworld.examples.scientific_inputs for a complete import example: an existing water property package, six synthetic cooling-curve records in two experiment groups, and two heat-loss parameters applied through the native model declaration. The example emits JSON with sources, uncertainties, train/validation counts and public pressure readings. It performs no fitting.

    chemworld.data.scientific_inputs.ScientificTable.from_json(text) reads either parameter or measurement tables. Columns declare a quantity, unit, role, finite valid range and reference state. Each cell contains value, unit, standard uncertainty, uncertainty_note and quality. A source has an explicit citation, version, licence declaration and synthetic, measured or literature label. Unknown uncertainty stays None; it must have an explanatory note. Celsius values receive the temperature offset, while uncertainty uses the scale only.

Measurement splits are train, validation, test or unused. All rows in one experiment group must share a split. Parameter rows use parameters. Missing or invalid observations remain in the table with their quality flags; conditions and parameters must be valid. The importer rejects duplicate identities, unknown columns, incompatible units and valid values outside their declared range.

    table.to_csv() writes a wide CSV with the row identifiers and five cell fields per quantity, for example pressure.value and pressure.uncertainty. ScientificTable.from_csv(text, metadata) reads it using the same contract; metadata is table.to_dict() with the rows entry removed. No split is inferred or randomized. table.summary() reports complete counts, and table.rows_for("validation") selects the declared holdout.

The curated example preserves unknown upstream table redistribution terms and unquantified uncertainty; successful parsing does not establish a licence or calibration.

    chemworld.world.parameter_inputs.bind_parameter_row(physics, table, row_id, targets) applies one parameter row to new model configuration. The application supplies ModelParameterTarget objects independently of the input, defining the installed model/version, binding, numeric field path and quantity contract. The function returns new physics and an import receipt; pass that configuration through the usual composition/session constructor. Model codecs validate coupled changes together. Measurement tables cannot be bound as parameters, and imports never write observations or inventory into a running world.

from chemworld.physchem.battery_impedance import battery_impedance
